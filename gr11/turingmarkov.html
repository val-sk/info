Зачем нужно определение алгоритма?

Элементы теории алгоритмов

Что такое алгоритм?

  • Алгоритм — точный набор инструкций для исполнителя, приводящий к решению задачи за конечное время.
  • Термин ввёл Г. В. Лейбниц (XVII век), от имени аль-Хорезми (IX век).
  • Древнейший пример — алгоритм Евклида для НОД.

Свойства алгоритма

  • Получает на вход дискретный объект.
  • Обрабатывает его по шагам, строя промежуточные объекты.
  • Может закончиться или зациклиться.
  • Если заканчивается — результат это последний построенный объект.
  • Если зацикливается или аварийно завершается — результат не определён.

Алгоритм и исполнитель

  • Алгоритм рассчитан на конкретного исполнителя с понятными ему командами.
  • Задание для исполнителя — программа на формальном языке.
  • Алгоритм = программа для некоторого исполнителя.

Уточнение понятия

  • Любые объекты можно закодировать как символьные строки.
  • Любой алгоритм сводится к преобразованию одной строки в другую.
  • Достаточно рассматривать алгоритмы, работающие с двоичными последовательностями.

Проблема разрешимости

  • Долгое время считалось, что для любой задачи можно найти алгоритм.
  • В 1931 году К. Гёдель доказал теорему о неполноте: в любой сложной формальной системе есть утверждение, которое нельзя ни доказать, ни опровергнуть.
  • Возникло предположение о алгоритмической неразрешимости некоторых задач.

Теория алгоритмов

  • Для строгих доказательств потребовалось математическое определение алгоритма.
  • Теория алгоритмов изучает:
    • алгоритмическую неразрешимость;
    • сложность алгоритмов;
    • оценку качества алгоритмов.
  • Вклад: Тьюринг, Пост, Чёрч, Клини, Марков.

Универсальный исполнитель

  • Понятие алгоритма «привязано» к исполнителю и языку программирования.
  • Это не позволяет определить алгоритм как математический объект.
  • Универсальный исполнитель — может моделировать работу любого другого исполнителя.
  • Для любого алгоритма существует эквивалентный алгоритм для универсального исполнителя.

Модель универсального исполнителя

  • Система команд должна быть как можно проще.
  • Модель должна содержать:
    • «процессор» — система команд и способ их выполнения;
    • «память» — способ хранения данных;
    • язык программирования;
    • способ ввода данных;
    • способ вывода результата.

Эквивалентность моделей

  • В середине XX века предложено несколько моделей универсальных исполнителей.
  • Доказано, что все они эквивалентны друг другу.
  • Алгоритм для одного универсального исполнителя можно запрограммировать для всех остальных.
  • Это позволяет доказывать разрешимость или неразрешимость задач.

Связь с определением алгоритма

  • Универсальный исполнитель решает проблему строгого определения алгоритма.
  • Любой алгоритм может быть представлен как программа для универсального исполнителя.
  • Это основная идея теории алгоритмов.
