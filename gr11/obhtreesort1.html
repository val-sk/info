Сортировка
бинарным деревом

Tree Sort — вставляем числа в BST, потом обходим по порядку.
Никаких классов, только списки и рекурсия.

← → или кнопки снизу для навигации

Идея алгоритма

Бинарное дерево поиска (BST) хранит элементы так: в левом поддереве узла — всё меньше, в правом — всё больше.

1. Вставка
Пробегаем дерево, сравнивая с корнем, и кладём число влево или вправо.
2. Обход
Рекурсивный inorder: левое → корень → правое. Даёт отсортированную последовательность.
3. Результат
Обход по inorder возвращает числа по возрастанию — готовая сортировка.

Шаг 1. Вставка в дерево

Узел — это список [value, left, right]. Пустой узел — None.

def insert(node, value):
    if node is None:
        return [value, None, None]     # новый лист
    if value < node[0]:
        node[1] = insert(node[1], value) # идём влево
    else:
        node[2] = insert(node[2], value) # идём вправо
    return node

Шаг 2. Обход по возрастанию

Классический inorder: сначала левое поддерево, потом корень, потом правое.

def inorder(node):
    if node is None:
        return []
    return inorder(node[1]) + [node[0]] + inorder(node[2])

А теперь — сама сортировка:

def tree_sort(arr):
    root = None
    for x in arr:
        root = insert(root, x)
    return inorder(root)

Шаг 3. Пошагово: строим дерево

Вставляем числа [5, 3, 8, 1, 4, 7, 9] по одному.

  1. 5 → корень
  2. 3 < 5 → влево
  3. 8 > 5 → вправо
  4. 1 < 5, 1 < 3 → левее 3
  5. 4 < 5, 4 > 3 → правее 3
  6. 7 > 5, 7 < 8 → левее 8
  7. 9 > 5, 9 > 8 → правее 8

Шаг 4. Пошагово: inorder-обход

Для каждого узла: левое → корень → правое. Собираем в список.

Порядок посещения:

  1. Стартуем в 5, идём влево в 3
  2. Из 3 — влево в 1, дальше некуда → забираем 1
  3. Возврат в 3 → забираем 3
  4. Из 3 — вправо в 4 → забираем 4
  5. Возврат в 5 → забираем 5
  6. Вправо в 8, оттуда влево в 7 → 7
  7. Возврат в 8 → 8, затем вправо в 9 → 9

Итог: [1, 3, 4, 5, 7, 8, 9]

Шаг 5. Запуск

# Собираем всё вместе
arr = [5, 3, 8, 1, 4, 7, 9]
result = tree_sort(arr)
print(result)   # [1, 3, 4, 5, 7, 8, 9]

Никаких классов. Только:

  • списки [value, left, right] как узлы,
  • две рекурсивные функции: insert и inorder,
  • одна функция-обёртка tree_sort.

Сложность

O(n log n)
средний случай
(сбалансированное дерево)
O(n²)
худший случай
(уже отсортированный вход)
O(n)
дополнительная память
под узлы дерева

На практике tree sort уступает quicksort/mergesort из-за накладных расходов на память и плохого поведения на отсортированных данных. Но как учебный пример — идеален.

Полный код программы

# Сортировка бинарным деревом (Tree Sort)
# Узлы — списки [value, left, right]

def insert(node, value):
    if node is None:
        return [value, None, None]
    if value < node[0]:
        node[1] = insert(node[1], value)
    else:
        node[2] = insert(node[2], value)
    return node

def inorder(node):
    if node is None:
        return []
    return inorder(node[1]) + [node[0]] + inorder(node[2])

def tree_sort(arr):
    root = None
    for x in arr:
        root = insert(root, x)
    return inorder(root)

if __name__ == "__main__":
    data = [5, 3, 8, 1, 4, 7, 9]
    print(tree_sort(data))   # [1, 3, 4, 5, 7, 8, 9]
Формирующее оценивание · вопрос 1 из 5
Вопрос 1
Что вернёт вызов inorder([5, [3, None, None], [8, None, None]])?
✓ Верно!Inorder обходит «лево → корень → право»: сначала 3, потом 5, потом 8.
✗ Не совсем.Inorder — это лево → корень → право. Для корня 5 с левым 3 и правым 8 порядок будет [3, 5, 8].
Формирующее оценивание · вопрос 2 из 5
Вопрос 2
Какая сложность tree sort в худшем случае?
✓ Верно!Если вход уже отсортирован, дерево вырождается в «ленту» глубиной n, и каждая вставка занимает O(n) — итого O(n²).
✗ Не то.O(n²) — худший случай: когда вход уже отсортирован, дерево превращается в «ленту», и каждая из n вставок идёт по n узлам.
Формирующее оценивание · вопрос 3 из 5
Вопрос 3
Что произойдёт, если на вход tree_sort подать массив [1, 2, 3, 4, 5]?
✓ Верно!Каждое следующее число больше предыдущего → всегда идём вправо. Дерево превращается в «ленту», но inorder всё равно вернёт [1,2,3,4,5].
✗ Нет.Ошибка не возникнет — код корректен. Но дерево действительно станет «лентой»: каждое следующее число больше, поэтому всегда идём вправо. Сортировка сработает, но за O(n²).
Формирующее оценивание · вопрос 4 из 5
Вопрос 4
Какую роль играет рекурсия в функции insert?
✓ Верно!Каждый вызов insert сравнивает значение с текущим узлом и рекурсивно идёт в левого или правого ребёнка, пока не достигнет None — туда и встанет новый лист.
✗ Не то.insert не сортирует, не печатает и не чистит дубликаты. Её задача — найти место для нового значения, спускаясь по дереву рекурсивно.
Формирующее оценивание · вопрос 5 из 5
Вопрос 5
Какое свойство BST гарантирует, что inorder-обход даст отсортированный список?
✓ Верно!Именно это свойство (left < node < right) делает inorder-обход отсортированным: сначала все меньшие, потом сам узел, потом все большие.
✗ Не то.Ключевое свойство BST: слева от узла — всё меньше, справа — всё больше. Благодаря этому inorder («лево → корень → право») автоматически выдаёт значения по возрастанию.
